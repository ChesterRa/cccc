## 方法与隔离

- 真实浏览器使用 agent-browser 驱动原生页面；组件测试用现有 Vitest，后台集成用现有 Rust 测试。每层分别留证，不互相冒充。
- 破坏性、失败和版本切换场景使用独立 Home、工作组、外部 CLI 与 mise 夹具，不挂载业务登录；夹具执行真实进程、真实文件安装与删除，不调用供应商模型。
- Web 中提交操作、启动/停止 Actor；后台读取状态、进程与文件证据做交叉核验。预置夹具、故障注入可以使用脚本，不能用 API 代替标注为 Web 的用户步骤。
- 发布实例核验同一程序/网页哈希、页面、持久化、健康及既有 Actor/桥接；标准对照不得改变。
- 软件分发逐供应商验证独立于上述通用流程；供应商登录和模型推理不属于本次 CLI 生命周期验收。

## 可重复自动化入口

- 组件：`cd web && npm test -- src/components/modals/settings/CliManagementTab.test.tsx`。
- 状态/安装/卸载：`cargo test -p cccc-pair-core -p cccc-pair-daemon --lib cli_management`；真实供应商测试默认忽略，必须在获准无凭据实验环境单独运行。
- HTTP 与 Runtime：`cargo test -p cccc-pair-web --test cli_management --test runtimes`。
- Actor 集成：`cargo test -p cccc-pair-daemon managed_cli`。
- 浏览器执行与部署证据在内部验收记录维护，不向公开仓库放入真实服务器信息和账号数据。

## 本轮发现与修正

- 原记录缺少开始/结束时间和明确手动/计划标签：补齐展示，保留后台 `Job`/`jobs` 协议。
- 删除 URL 后原生 Web fallback 返回 HTML 200，不是配置成功；回归检查响应类型、旧配置不变及 Daemon 操作不再处理，不为这个已删除功能新增专属路由。

## 执行结果与边界

- 核心 8、Daemon 22、Actor 实际启动 3、HTTP/Runtime 4、前端 15，共 52 项回归通过；默认忽略的真实供应商安装测试 1 项不计入通过数。本次未重新下载全部供应商软件，既有逐供应商安装证据见功能规格。
- 26 条浏览器操作记录包含手动和计划来源；开始/结束区间无重叠。将后台 ISO 时间按浏览器相同的 `toLocaleString()` 转换后逐项核对页面，不仅检查时间先后关系。
- 杀停无凭据隔离实例时，一项运行、一项排队。重启后运行项成为 `interrupted`，排队项继续成功，旧成功记录未重放。存储损坏时出现明确错误，恢复原文件后错误消失且记录不丢。
- 浏览器网络故障注入使用精确 URL；未命中的通配表达式不算断网通过。日期控件采用原生分段输入并读取实际值；仅自动化工具返回 Done 不算成功。工具等待、过期引用及文案大小写错误已按真实页面重试核验，没有修改产品控件来迁就工具。
- 受限身份仍可使用原生允许的个人配置页面；本功能只要求全局 CLI 管理不可访问，不改变 CCCC 既有权限体系。
- 仅部署获准的开发实例；没有安装或升级业务 CLI、启用业务自动计划、发送聊天或调用模型。供应商登录、真实模型推理及其他平台不在本次生命周期回归范围内。
