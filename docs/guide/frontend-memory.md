# 前端内存与工作组缓存

浏览器任务管理器里的渲染进程内存不等于 JavaScript 堆：它还包含原生对象、图片、字体、编译代码、扩展隔离世界等。高占用本身不能证明内存泄漏。Vite 开发页面也不能直接代表生产构建的占用。

## 缓存保留策略

- 工作组视图快照最多保留最近使用的 8 组，写入后 5 分钟过期。
- 过期会真正删除引用；即使没有下一次读取，也会由单一定时器清理。读取不会延长新鲜度期限。
- 普通聊天缓存最多保留最近使用的 8 组；当前组、正在流式输出或加载历史的组不被驱逐。保护依据是 pending/streaming 会话、正在输出的事件或尚未关联会话的排队占位；completed/failed 会话保留的展示记录不阻止淘汰。因此所有组都处于受保护状态时，聊天缓存可以临时超过 8 组。
- 淘汰只作用于可从服务端重新读取的内存副本，不删除账本、磁盘历史或发送框草稿。再次进入被淘汰的工作组时重新加载消息。
- 单组原有的消息、原始流式事件上限继续有效。

## 排查方法

1. 记录当前组、可见性、正在进行的任务。不要把后台空闲采样当作前台繁忙场景的结论。
2. 在 DevTools Performance monitor 或 CDP 中采样堆、DOM 节点、事件监听器和脚本耗时。
3. 比较同一状态下多次垃圾回收后的基线；临时对象增长后能够回落与持续保留对象应分开判断。
4. 连续切换超过 8 个工作组，再重复一轮，检查缓存数量、消息重新加载及活动流是否正常。
5. 对仍持续增长的场景用堆快照检查保留路径。涉及真实聊天内容的原始快照留在本地，不提交进公共仓库。

## 回归命令

在 `web/` 中运行：

```sh
npm test -- src/stores/groupMemoryRetention.test.ts
npm test
npm run typecheck
npm run build
```

`groupMemoryRetention.test.ts` 覆盖闲置过期释放、容量驱逐、读取不续期、定时器清理、工作组回访、晚到更新与活动任务保护，以及完成输出后的容量回收、无输出事件时的等待会话保护、排队占位及终态记录淘汰。

`useSSE.headlessReplay.test.tsx` 还覆盖带/不带消息 ID 的失败通知：错误展示记录处于终态，重复回放不重复创建，并能在切组后淘汰。

## 本次验证的边界

短时后台采样中，回收后的堆基线、DOM 节点和事件监听器均保持稳定；这不能排除长时间运行、终端、语音或其他交互路径的泄漏。本次修复针对已复现的跨组缓存保留，不承诺整个浏览器进程立即归还所有常驻内存。
