# CCCC v0.4.58 Release Notes

CCCC v0.4.58 makes documents in a conversation easier to read and fixes the
resting phone composer. Markdown attachments switch between their rendered view
and their unchanged source, and HTML attachments, Group HTML files and HTML from
the raw GitHub and gist hosts open as a static document preview instead of only
as a download. On a phone, the empty composer at rest keeps its controls on one
row again.

This release changes only CCCC Web; the daemon's operations and the runtimes are
unchanged. A daemon restart works as before: agents that CCCC started stop with
the daemon, and a turn that was running does not continue when CCCC starts them
again; sessions you started yourself keep running.
[What a daemon restart keeps](../guide/operations.md#what-a-daemon-restart-keeps)
has the details. This release covers the changes since v0.4.57.

## Before You Upgrade

Before upgrading, let sends and recordings finish. Restore or discard waiting
sends, then send or copy every unsent draft, restored ones included, and save
unsaved edits in **Files**: all of these live only in the open page. Check whether
a message already arrived before sending it again.

Upgrade the CCCC executable, restart the daemon and Web the way you usually launch
them, and reload open CCCC pages. The standalone installer behind `cccc update`
stops a running daemon and starts it again from the new version. Before a pip
upgrade, run `cccc daemon stop` and close any foreground CCCC so pip can replace the
executable, especially on Windows. A daemon left running keeps the previous version.
Runtime history stays in `CCCC_HOME`.

## Read Documents in the Page

Markdown attachments, and Markdown links opened in the page, switch between the
rendered view and the unchanged source with **View source** and **Preview**, the
control that workspace files already have. Switching does not download the file
again. The control sits in the title bar of the resource panel, of each side of a
split view and of the preview dialog, so a document gets no extra toolbar row.
The keys in an attachment's title bar now share one size with the **Files**
toolbar.

HTML attachments, Group HTML files and HTML from `raw.githubusercontent.com` or
`gist.githubusercontent.com` now open in the same places as a static document.
The preview reuses the sanitizer that workspace HTML files already use: scripts,
event handlers, frames and linked stylesheets are removed, form controls are
disabled, and the frame has no permission to run scripts. External resources are
not loaded; inline styles and embedded images are supported. Ordinary clicks on
web links open them outside the preview; in-page links scroll within it. Mail
links are handed to the browser. **View source** shows the HTML as text, up to
its first 1 MiB.

An attachment has no directory, so its relative images, stylesheets and sibling
files are not resolved; download the original when you need them. HTML up to
20 MiB previews in full, including embedded images in static slides; larger HTML
shows its first 1 MiB as source only, with a notice, instead of rendering a broken
page. Pages keep their own size and margins: wide slides stacked in a centered
column start at the left, and the rest of each slide scrolls into view sideways. In
**Files**, HTML over the 1 MiB editing limit now previews the same way and stays
read-only. A panel tab that holds an HTML document keeps that kind when the
page is reloaded.

## One Row for the Phone Composer

On a phone, the empty composer collapses to a single row when it is not focused.
The template button had no place in that row and dropped to a second line. The
row now holds attach, the template button, the input and voice. **Send** comes
back with the full layout as soon as the input is focused; an empty draft at rest
has nothing to send. A send in flight keeps the full layout, so its progress and
**Stop waiting for upload** stay visible if focus leaves the composer during an
upload.

## Known Limitations

- The HTML preview is a document view, not a running website or application.
  Scripts, forms and external resources stay disabled, and an attachment's
  relative resources are not resolved.
- **View source** shows at most the first 1 MiB of a file, and HTML over the
  20 MiB preview limit shows only that source; download the file for the rest.
- Pages are not scaled to fit. Wide slides laid out another way can still lose
  their left part in a narrow preview; download the file and open it in a browser
  to see it as designed.
- A daemon restart still stops the agents that CCCC started, as described above.

## Validation Scope

Release preparation ran rustfmt, Clippy and the Rust tests in CI's three groups
in isolated homes, so each of the 4,117 tests that are not ignored among the 4,127
listed ran once and passed. That run was on the release candidate before its last
Web fixes, and the Rust code has not changed since. On the final code: the Web
check and the Web tests (5,083 tests in 675 files), the repository's Python tests
(128), git diff --check, and the version parity and release identity checks for
v0.4.58. Apart from the version, the Rust and Python code is unchanged. After the
last edit to these notes, git diff --check ran again.

Both changes were checked in isolated headless Chrome, and both maintainers
reviewed the whole range again before release:

- Document previews: Chinese and Japanese at desktop and phone width, and English
  at desktop width, covering rendering, the source switch, blocked scripts, forms
  and external requests, links opened without an opener, and truncated HTML.
- After a test of the release candidate, the larger HTML limit, wide slides and the
  key sizes: synthetic HTML of 5.5, 10 and 20 MiB at desktop size and in phone
  emulation; in **Files** at desktop size, a 5.5 MiB HTML file and a synthetic deck
  of wide slides; eleven synthetic layouts at 594 and 390 px, among them deliberate
  crops, scroll containers, media queries and resizing; real slide files, measuring
  layout only, at desktop and phone widths and after maximizing and restoring the
  panel; and the keys of the attachment title bar and the preview dialog in
  Chinese, English and Japanese at desktop, narrow and touch phone widths.
- The phone composer: phone widths from 320 to 430 px in Japanese, Chinese and
  English, dark and light, a short touch landscape, and desktop.

These are Linux checks; Windows and macOS were not tested locally. Phone widths
were emulated in desktop Chrome, not checked on phones.
