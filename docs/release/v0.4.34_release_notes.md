# Draft: CCCC v0.4.34 Release Notes

This is a future release draft. The current Python and Rust package version remains
`0.4.33`; no `v0.4.34` release is implied by this document.

`v0.4.34` will bring the native Rust implementation onto the same product and release
line as CCCC's Python distribution, adds Cline as a first-class runtime, and
tightens the authorization and release boundaries that matter when CCCC is used
across multiple Working Groups.

## One CCCC Release, Two Installable Implementations

Python and Rust will use the same `0.4.34` product version and `v0.4.34` tag. The
Python package remains available through PyPI. The native distribution can be
installed from crates.io as `cccc` or from the verified GitHub archives for Linux,
Intel and Apple Silicon macOS, and Windows.

Both implementations use the same `CCCC_HOME`, group documents, append-only
ledgers, actor contracts, daemon IPC model, MCP surface, and Web frontend. Native
release candidates are built and smoke-tested on every supported archive target.
The crates.io release publishes implementation crates in dependency order before
the public `cccc` package, and the process can safely resume after a partial
registry publication.

## Cline Joins the Runtime Catalog

Cline is now covered as a formal PTY runtime rather than a custom command. CCCC
can discover the installed CLI, create actors with the supported TUI defaults,
install or repair the `cccc mcp` stdio server through Cline's own MCP command, and
show the runtime consistently in the CLI, diagnostics, Web actor editor, profiles,
and runtime documentation.

The integration uses Cline's configuration boundary instead of editing unrelated
Node or npm state. Re-running setup repairs the single named `cccc` server entry,
which keeps installation deterministic when the CCCC executable path changes.

## Safer Multi-Group Web Access

The supported `?token=` URL remains available for bootstrapping a browser session.
Its transport does not change what the token may access: a Group-scoped token sees
global notifications only for its assigned Groups.

The global SSE channel now contains routing metadata only. Message bodies and
other complete event fields stay on the authorized per-Group stream. Capability
blocking is also treated as an administrative operation, closing a route that
previously accepted scoped credentials.

## More Predictable Recovery and Delivery

The Rust backend closes a broad set of compatibility gaps around actor recovery,
inbox cursor migration, Group Bridge route health and revocation, tracked sends,
headless delivery, daemon shutdown, and Web terminal replay. The Web UI also keeps
chat and terminal anchors stable across view changes and reconnects, reducing the
number of situations where recovered state looked stopped, incomplete, or
read-only.

Python inbox cursors now use the ledger's append order as their authority too.
Two events with the same timestamp—or a clock adjustment that makes a later event
look older—can no longer cause unread work to be skipped.

## Upgrade Notes

- No ledger or Group data migration is required. Stop the active daemon before
  switching between Python and native Rust installations; never run both daemons
  against the same `CCCC_HOME` concurrently.
- Existing Access Tokens continue to work. Group-scoped tokens now receive less
  data from the global stream, as intended; per-Group views continue to receive
  complete authorized events.
- Existing custom Cline actor commands remain valid. New actors use CCCC's formal
  Cline defaults, and `cccc setup --runtime cline` can repair the MCP entry.
- A manual release-workflow dispatch performs build and verification only. Package
  and GitHub publication require a matching pushed `v0.4.34` tag.

## Why Upgrade

Upgrade when you want a supported native CCCC installation, use Cline alongside
other agents, operate Group-scoped Web access, or depend on the Rust backend's
delivery and recovery parity. This release deliberately keeps the product model
unchanged: one CCCC contract, one version, and two implementation choices.
