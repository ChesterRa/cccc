# CCCC v0.4.34-rc2 Release Notes

This release candidate validates the complete pip distribution with its bundled
Rust implementation, plus an optional experimental standalone Rust preview,
before the stable `v0.4.34` release.

`v0.4.34-rc2` brings the native Rust implementation onto the same product and release
line as CCCC's Python distribution, adds Cline as a first-class runtime, and
tightens the authorization and release boundaries that matter when CCCC is used
across multiple Working Groups.

## One CCCC Installation, Two Implementations

Python uses PEP 440 `0.4.34rc2`, Rust uses SemVer `0.4.34-rc2`, and both map to
the canonical `v0.4.34-rc2` tag. The release candidate is published to TestPyPI.
The stable and recommended `cccc-pair` distribution keeps Python as its initial
default and bundles a private Rust executable in supported platform wheels.
Other pip platforms retain the universal Python fallback. Linux x86-64, Intel
and Apple Silicon macOS, and Windows x86-64 users may also evaluate an
experimental standalone Rust preview from GitHub Pages without installing Rust
or Python; that preview has no Python fallback or implementation switching.

Both implementations use the same `CCCC_HOME`, group documents, append-only
ledgers, actor contracts, daemon IPC model, MCP surface, and Web frontend. Native
wheel candidates are dependency-repaired, installed, and switched in both
directions on every supported target. Standalone binaries execute on each native
build host, and final installer candidates are exercised on Linux and Windows. A
dedicated interop gate covers the shared persisted-state contracts. The complete
source, universal, and native artifact set is then published once to the
appropriate Python package index (TestPyPI for this RC), and tags no longer
publish a parallel crates.io product.

`cccc rust [command ...]` and `cccc python [command ...]` persist the selected
implementation and optionally run a command. `cccc status` reports the selected,
running, and available implementations. The launcher validates exact payload
version parity before a switch, explicitly replaces the active Web/daemon pair,
and never silently falls back. In the experimental standalone preview,
`cccc update` uses the website installer; in the recommended pip installation it
updates both implementations as one product.

## Cline Joins the Runtime Catalog

Cline is now covered as a formal PTY runtime rather than a custom command. CCCC
can discover the installed CLI, create actors with the supported TUI defaults,
install or repair the `cccc mcp` stdio server through Cline's own MCP command, and
show the runtime consistently in the CLI, diagnostics, Web actor editor, profiles,
and runtime documentation.

The integration uses Cline's configuration boundary instead of editing unrelated
Node or npm state. Re-running setup repairs the single named `cccc` server entry,
which keeps installation deterministic when the CCCC executable path changes.

## Safer Multi-Group Web Access

The supported `?token=` URL remains available for bootstrapping a browser session.
Its transport does not change what the token may access: a Group-scoped token sees
global notifications only for its assigned Groups.

The global SSE channel now contains routing metadata only. Message bodies and
other complete event fields stay on the authorized per-Group stream. Capability
blocking is also treated as an administrative operation, closing a route that
previously accepted scoped credentials.

## More Predictable Recovery and Delivery

The Rust backend closes a broad set of compatibility gaps around actor recovery,
inbox cursor migration, Group Bridge route health and revocation, tracked sends,
headless delivery, daemon shutdown, and Web terminal replay. The Web UI also keeps
chat and terminal anchors stable across view changes and reconnects, reducing the
number of situations where recovered state looked stopped, incomplete, or
read-only.

Python inbox cursors now use the ledger's append order as their authority too.
Two events with the same timestamp—or a clock adjustment that makes a later event
look older—can no longer cause unread work to be skipped.

## Upgrade Notes

- No ledger or Group data migration is required. In the pip distribution, use
  `cccc rust` or `cccc python` to switch; the launcher owns stopping the active
  process pair and prevents two implementations from writing the same
  `CCCC_HOME` concurrently. The standalone preview contains Rust only.
- Existing Access Tokens continue to work. Group-scoped tokens now receive less
  data from the global stream, as intended; per-Group views continue to receive
  complete authorized events.
- Existing custom Cline actor commands remain valid. New actors use CCCC's formal
  Cline defaults, and `cccc setup --runtime cline` can repair the MCP entry.
- Manual release dispatches perform build and verification only. A pushed
  `v0.4.34-rc2` tag publishes the Python artifacts to TestPyPI; the experimental
  standalone archives, checksums, and installers are published only when an
  operator separately runs their workflow on that matching tag.

## Why Upgrade

Test this release candidate through TestPyPI when you want to validate the bundled
Rust implementation, use Cline alongside other agents, operate Group-scoped Web
access, or exercise the Rust backend's delivery and recovery parity. The product
model remains unchanged: one recommended pip distribution, one CCCC contract,
one version identity, and two implementation choices inside supported wheels.
