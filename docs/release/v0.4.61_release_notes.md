# CCCC v0.4.61 Release Notes

CCCC v0.4.61 lets you add sessions you already run on another computer to a
Group, alongside the sessions on this one. Codex, Claude Code, Pi and
OpenCode sessions registered with CCCC on a paired computer appear in the
same list, and their applications keep their own accounts, files and
approvals. Adding existing sessions moves into the Group's **Add Agent**,
and managing which sessions and computers may join moves into **Settings →
This instance → Session access**. A member who hands off work with a reply
request now hears about it when the handoff is accepted but never answered.

## Upgrading from v0.4.60

Use your usual update method. Your Groups, members, settings, messages, tasks
and Group connections are kept.
- The sidebar's **Connect sessions** entry is gone. Add running sessions
  from a Group's **Add Agent → Add existing sessions**, or start a Group
  from them with **New → Create from existing sessions**. Recheck, remove
  and restore sessions, and manage paired computers, in **Settings → This
  instance → Session access**.
- Sessions on another computer need CCCC v0.4.61 on both computers.
- Direct Group connection invitations you created before upgrading keep
  their state and expiry.
- `cccc setup` without `--runtime` no longer writes CCCC's MCP entry for
  every installed runtime. It lists how members that CCCC starts get its
  tools and what `cccc setup --runtime <name>` would write.
- Members that run `copilot` directly get CCCC's MCP server as a launch
  option, so CCCC no longer checks or repairs the `cccc` entry in your
  Copilot configuration. A wrapper command still needs a working MCP entry
  of its own.
- Native terminal members that run `agy` directly turn off Antigravity's
  feedback survey for that session only, unless their command already
  passes `--settings` (checked with Antigravity CLI 1.5.17). CCCC no longer
  writes this preference into your Antigravity settings, and leaves a value
  an earlier version wrote as it is.
- The FAQ explains how to remove the MCP entries CCCC wrote.
- Building from source now needs Rust 1.91 or newer.

## Add sessions from another computer (Experimental)

Pairing and delivery were tested between isolated networks on one Linux
machine, including a session running the official OpenCode V2.4.0 CLI. The
official Pi 1.6.0 CLI was tested in separate CCCC homes on one Linux
machine. End-to-end checks on separate physical computers, through a public
relay, and on macOS and Windows are pending.

- In **Add Agent → Add existing sessions**, choose **Pair a computer** under
  **Other computers**, pick the application and copy the command. On the
  other computer, in the account and CCCC home that own its sessions, run it
  (for example `cccc sessions node connect --runtime codex --ticket-stdin`),
  then paste the pairing ticket generated on this computer at its prompt.
  The ticket is not shown while you paste it, works for one computer and
  expires after ten minutes. Keep the connector's terminal open.
- Sessions registered with CCCC on that computer appear in their own section
  of the same list. If it is connected but none of its sessions are ready,
  the section tells you what to do in the original session. Pairing alone
  adds nothing to a Group; you still choose the sessions to add.
- Messages to a session on another computer go to its original application,
  which keeps its account, model, files, commands and approvals. CCCC does
  not copy its history or credentials. Its replies reach the Group as usual.
  Only text is carried for now: a message with attachments fails before it
  is handed over, and file, command and capability tools stay on that
  computer. Such a session sends text and replies only within the Group it
  was added to.
- Direct pairing uses UDP, which a firewall can block even on the same
  network. To use relay fallback, first enable Remote Access with an HTTPS
  public address in **Settings → This instance → Web Access → Remote
  Access**, then turn on **Public cross-network relay** in the pairing view
  or in **Settings → This instance → Session access**; it is off by default.
  The connector supports HTTP(S) CONNECT proxies configured through
  `HTTPS_PROXY` or `ALL_PROXY`, and supported static system proxies on macOS
  and Windows.
- If the encrypted connection fails, the connector suggests what to check.
  With a direct-only ticket, allow UDP or enable the public relay and use a
  new ticket. With a relay address in the ticket, check access to the hub's
  public HTTPS address and the connecting computer's proxy settings.
- If the selected application's command-line tool cannot be found, the
  connector names the missing command; once it is fixed, the same ticket can
  be pasted again before it expires. The native setup reminders and warnings
  from the first pairing print as plain text.
- **Settings → This instance → Session access** lists paired computers, with
  revoke and stop receiving. Revoking a computer closes its connection; its
  sessions keep running but can no longer reach the Group.

## A clearer list of existing sessions
- Each row shows the application, title and path. A session that cannot
  receive messages is marked **Unavailable to receive** and cannot be
  selected; when CCCC knows why, for example when Codex's shared backend has
  not opened the session, the row says so in plain words and offers **Check
  again**. Sessions that were never checked no longer carry a long note.
- **This computer** and **Other computers** above the list now switch
  between this computer's sessions and those of paired computers, instead of
  scrolling one long list. Sessions you selected on either side stay
  selected.
- The footer names the target Group and counts the sessions you selected on
  this computer and on other computers; the button says what it will do.
- When an agent explicitly addresses a local Codex session with Send or Send
  + Reply and CCCC detects that the session's host has exited, the send
  result flags that the session cannot receive. CCCC records the message and
  reports the outcome separately in its delivery status. The note suggests
  asking the owner to send a message in the original session or resume the
  conversation in Codex.

## Hear about handoffs that get no reply
- When a member accepts a **Send + Reply** handoff from another member but
  does not answer in time, the member who sent it, usually the foreman, now
  gets one reminder as well, listing every handoff that became overdue in
  that check. Each handoff is reminded once. Reminders to you are unchanged,
  and `reply_notice_after_seconds = 0` still turns reminders off.
- A native foreman reading a member's terminal through CCCC now reads the
  member it asked for, so it can look at the work behind an unanswered
  handoff when it is allowed to see that terminal.

## Chat and sidebar
- The send menu can switch the send key to Enter, with **Shift+Enter** for a
  new line. Ctrl+Enter (Cmd+Enter on macOS) remains the default shortcut and
  is available in either mode. The choice is kept in this browser.
- Click an audio file in a message to play or pause it; the Download button
  beside it downloads it. While a clip plays, a line along the bottom of its
  file shows how far it has got when its length is known. The page has no
  seek or volume control; download a long recording to move around in it.
- When Connect lists this instance, hover over or tap the product name in
  the expanded sidebar to open its details. Copy the public address from the
  card when one is available. The card stays reachable at 125% text size
  with the default sidebar width.
- In the expanded sidebar, each Group row keeps its status symbol,
  pending-reply count and ⋮ menu in fixed columns at the end of the row. Running Groups show a white
  triangle in the dark theme and a dark one in the light theme; the selected
  row uses its selection colour. A Group's connection count moves into its ⋮
  menu, as **Group connections · 2**.
- The sidebar still opens at 248 px and can now be dragged down to 200 px.
  At standard text size, the **New** button folds to its icon at 200 px so
  the product name stays visible.

## Terminal
- Read-only terminal windows follow the controlling window's size when the
  session reports size updates, so full-screen applications no longer draw
  over old frames or lose the start of lines. Smaller windows can scroll to
  see the rest. Older sessions without size updates still fit each viewer's
  window.

## Chet
- Chet's entry asks for attention when Chet waits for a permission, and when
  its Claude Code runtime waits for you to trust the workspace.
- The **Unattended on** status has its own row, so it stays readable on a
  narrow sidebar.

## Fixes
- The Web server now compresses responses with gzip instead of Brotli. In
  Linux tests, loading the same Web UI files left much less extra memory in
  the daemon, with about the same amount of response data.
- On a fresh home where Antigravity's first-run setup has not been
  completed, CCCC holds a new member's first messages until you finish the
  setup in its terminal, instead of typing them into the setup screens
  (#237). They are delivered automatically once setup is complete and the
  chat input box is visible. If the chat input box is visible and the
  messages are still waiting, choose **Done, send now**.
- Choosing the wrong file type for a branding image, or a file that is not a
  ZIP or has no Group copy manifest, now says so in your language and names the accepted
  formats or the **Export Group** button, instead of showing an English
  library error.
- Settings hints that still called this instance's settings "global" now say
  **This instance**.
- A session bound to a member that passes another member's ID to
  `cccc_headless` now gets an error for reads and writes, instead of
  silently using its own state. Use the member list to check another
  member's state.
- Common failures show the reason and a next step in English, Chinese and
  Japanese, keeping the original error code: delivery and shutdown errors, a
  project folder that does not exist or is not a folder, a message no member
  can receive, and a daemon that is not responding.
- An upload over its size limit (a presentation file, an avatar, a branding
  image, a Group copy package or chat attachments) now says it is too large
  instead of showing a parse error. Avatars, branding images and Group copy
  packages name the limit; the Group copy hint now gives the actual 1 GiB.
- On Linux and on Apple Silicon Macs running the native arm64 build, if the
  shared browser refuses the connection or a new window just after its last
  window closed, CCCC now keeps retrying within a ten-second window to
  reopen the agent window, instead of failing right away on a busy
  computer. The fix was verified on Linux.
- Typing a project path one key at a time keeps the suggested Group name in
  step with it; a name you typed yourself stays.
- Creating a Group from existing sessions asks you to select sessions.
  **Settings → This instance → Session access** says where sessions are added
  and offers a plain refresh, and its troubleshooting covers Pi and OpenCode.
- At phone width, the session access command wraps instead of being cut off,
  and the transcript visibility options show their full explanation.
- A Pi interaction that has expired no longer appears in the control panel,
  and no longer blocks new ones.
- Reminders are recognised only when CCCC itself sent them, so an ordinary
  notification can no longer suppress a real reminder.
- A message preview shortened to fit a native session's notification ends
  with "…".
- On desktop, when **This instance** cannot be chosen in Settings, a help
  button beside the scope switch explains why.
- Developer diagnostics and log loading follow the saved developer setting.
- On Windows, each daemon readiness check during startup is bounded by the
  startup deadline.
- Direct Group connections can now create permanent, reusable invitations.
  Each Group that requests a connection still needs your approval.
